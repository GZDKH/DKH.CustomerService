# EJ03 G3 owner-internal Copy and saved revision

This slice extends C1/C2 under [Customer #14](https://gitlab.xnata.com/gzdkh/services/DKH.CustomerService/-/issues/14). It supplies producer behavior and isolated tests; public typed transport, package publication, merge and deployment remain outside this submission. English is canonical; Russian translation is pending.

Existing-implementation decision: **extend**. Customer main `106e18e6cf5fd259ef28715c26a124da328544b7` already has `MutateCoreAsync`, Create receipts, account lifecycle locks, atomic append/CAS and retained revision/schema verification. Its hash covered a materialized draft, with no source-bound Copy intent; `GetAsync` selected only `CurrentRevision`. The verified owning issue was open/unassigned and there were no open Customer MRs at execution entry. Existing accepted C1/C2 and `typed-journal-owner-transport` are reused; no schema, migration, operation enum, receipt engine or public contract is added.

`MutateJournalCommand.Copy` is an owner-internal intent: source EntryId, positive source revision, explicitly chosen occurrence, and an explicit Retain or UnknownFallback choice. Retain rejects fallback fields. UnknownFallback requires bounded owner-confirmed private labels. The trusted adapter supplies identity and origin; this command is not a browser-facing authority mechanism.

The producer takes the existing owner lifecycle and account+Create+key locks. Ordinary Create retains its exact canonical identity shape. Copy hashes its discriminator, source identity, occurrence, trusted origin and options before source lookup, using the existing Create receipt namespace and 24-hour lifetime. Matching unexpired retries return the saved result without inspecting the source again. Changed intent and Create/Copy key collisions conflict.

Only a first execution or an expired receipt reads the ordinarily readable owned source revision and verifies its retained payload and profile binding. It reconstructs bounded content, including tags, score, private pack/lot labels and exact observations, from that immutable body. Profile context comes from the verified frozen schema. It then creates through the existing atomic producer. Retain reuses an owned unknown reference; Product retention fails closed until the EJ04 adapter exists. An explicit unknown fallback creates a private unknown reference with no Product/Release grant. Frozen profile/observation retention is private history, not a new Catalog authorization.

`GetJournalEntryQuery.Revision` selects a saved mutation's exact EntryId+ResultRevision; omission still reads the current revision. Under the owner lifecycle lock, the producer first checks current destination ownership and ordinary visibility/deletion, then verifies the requested immutable revision/schema. It returns no current mutable target/date/score/body/header fields. Later edits do not change the historical result. Deleted destinations deny body serving with NotFound, including when an internal result-only receipt can still replay. Delete result replay does not expose retained bodies.

Acceptance is recorded in [the G3 test receipt](../../openspec/changes/typed-journal-owner-transport/evidence/g3-producer-tests.json) and implemented by `JournalCopyIntentTests` and `JournalCopyReplayHostTests`. Real PostgreSQL tests cover concurrent retries, source edits/deletion/corruption, immutable old source selection, changed intent/options/origin, Create collision/hash compatibility, exact original destination revision after target/date/score edits, deleted-body confidentiality, foreign/missing/lifecycle/service denial, Product fail-closed, private fallback, frozen exact decimals/time, expiry and post-SaveChanges rollback.

G1 trusted origin and G2 persisted cursor protection remain unavailable. G4 typed/raw-wire ingress, approved protobuf/version/package and public adapters remain pending. The existing fixture supplies trusted owner-internal inputs and exercises the real producer through an authenticated HTTP/2 host; it is not a new generated typed journal API or full RT03 acceptance. No whole EJ03, 49-master, 24-stage or main140 completion is inferred.
