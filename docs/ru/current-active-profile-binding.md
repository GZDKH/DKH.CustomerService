# Текущая связь активного профиля

Приватный метод `CurrentProfileBindingService/GetMyActiveProfileBinding` в namespace v2 принимает пустой запрос. Он возвращает настоящий `CustomerProfile.Id` и выбранную витрину; ID аккаунта, членства, связанной личности и JWT sub не заменяют ID профиля.

Используются существующая проверка персонального Bearer (`iss`, непрозрачный `sub`, `personal:v1`) и политика CustomerSelfAccess. Один непустой UUID витрины должен совпадать с контекстом Platform. Повторные, некорректные и противоречивые селекторы отклоняются.

После штатного поиска аккаунта один свежий запрос повторно проверяет единственность личности, активный аккаунт, единственное активное членство и точную связь с активным Linked-профилем. Отозванные, удалённые, заблокированные, чужие и неоднозначные связи отклоняются. Метод не создаёт и не восстанавливает данные, не вызывает Delivery и не выдаёт доступ к контактам.

Ответ содержит только профиль и витрину. Это текущее наблюдение, без выдуманной версии, срока, grant или согласия. Потребители обязаны отдельно проверять актуальность и собственные полномочия. Контракт 1.12 — кандидат; публикация SDK и runtime ещё требуют штатных проверок после main45038. Пять новых PostgreSQL случаев локально только скомпилированы/обнаружены. Customer52 и исходная83 остаются открытыми.
